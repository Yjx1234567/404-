# CodeOJ 一键启动与加载失败修复

## 当前证据

用户反馈旧深色页面与题库加载失败，要求简化启动。通过命令行 HTTP 和 WSL 检查确认：

- 服务实际运行在 Ubuntu-22.04 的 `/root/oj_platform`，Windows 中的新 public 尚未同步，在线 CSS 仍是旧版。
- 8080 确由该项目的 oj_server 监听；不能仅凭“Server starting”日志判断启动成功，因为该日志先于端口绑定。
- 未登录访问题库返回 401，属于正常鉴权契约。以现有默认管理员登录后，题库返回 200，共 100 道题；测试会话已注销。
- 浏览器缓存的 localStorage 用户信息并不代表 HttpOnly Cookie 会话仍有效。旧客户端没有处理受保护接口的 401，且登录页会仅凭缓存跳回题库。
- 当前数据库已有 solution 列，但新建数据库 DDL 与旧迁移缺少该列，需要补齐以保证其他安装环境可用；不把它描述成本次已证实的根因。

## 实现选择

继续使用已部署的 WSL C++ 与 MySQL，不换框架、不创建替代静态演示。

1. `启动OJ.bat` 调用当前目录中的 PowerShell 包装，再明确使用 Ubuntu-22.04 调用 Python 标准库启动引擎。
2. 每次自动同步当前前端与必要源码；保留 WSL 的现有配置与全部业务数据。只有后端变化时才增量编译，不删除 build 或重置管理员。
3. 运行目录 HTML 的 CSS/JS 引用带内容摘要，更新资源时自动换缓存版本。
4. 自动启动 MySQL；已有本项目健康服务复用，新进程后台运行。识别归属后才允许停止，不杀未知端口占用者。
5. 用实际 HTTP 响应和 CSS 内容校验就绪，成功才打开登录页。启动脚本的正常用户操作会打开浏览器；代理执行验证一律使用 `-NoBrowser`，不进行浏览器自动化或视觉检查。
6. 受保护 API 的 401 清除本地登录缓存并回登录页，登录/注册错误保持原页；网络与格式错误显示具体原因。
7. 新增 `停止OJ.bat` 与 VS Code 启动/停止任务；旧 2/3 号入口兼容转发到同一启动流程。

## 首次环境约束

一键入口面向本项目已经部署的 Ubuntu-22.04 环境。它不会隐式安装/删除发行版、安装软件包、重置数据库或改账号密码。全新机器仍需一次性安装依赖并执行 setup.sh；已部署后的日常启动不需要任何复制命令或重复全量部署。
